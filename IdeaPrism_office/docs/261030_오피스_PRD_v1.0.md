## 1. 개요

### 1.1 한 줄 정의
AI 팀장 봇(Claude Code)들이 일하는 모습을 **3D 공유오피스 화면**으로 보면서 업무를 지시하고, 결재하고, 산출물을 검토하는 **로컬 전용 대시보드 앱**.

### 1.2 목표

| # | 목표 | 측정 기준 |
|---|---|---|
| G1 | 팀장 3명에게 화면에서 바로 업무 지시 | 클릭 → 입력 → Claude Code 실행까지 3단계 이내 |
| G2 | 누가 무엇을 하는지 한눈에 파악 | 스크롤 없는 1화면(1440×900)에 전원 상태 표시 |
| G3 | 위험한 작업은 대표가 결재 | 파일 쓰기·명령 실행 권한 요청이 화면 결재로 처리됨 |
| G4 | 산출물 품질 검토 | 팀장이 만든 파일을 diff로 보고 커밋 |
| G5 | 지식 축적 | 재사용 지식만 wiki/raw → knowledge로 정리 |
| G6 | 쓰는 재미 | 캐릭터 이동·표정·대표실 꾸미기·음악 |

### 1.3 비목표 (하지 않는 것)

| 항목 | 이유 |
|---|---|
| 웹 배포·외부 접속 | 로컬 전용. `127.0.0.1`에만 바인딩 |
| 팀장끼리 자율 토론 | 불안정. 협업은 handoff 파일로만 |
| 팀원(벤·뮤즈)의 독립 봇 실행 | 1차 범위 밖. 화면에는 표시만 (2차: 서브에이전트) |
| 실시간 3D 엔진(Three.js 등) | CSS 3D로 충분. 성능·유지보수 단순화 |

## 2. 핵심 개념

| 개념 | 정의 |
|---|---|
| **팀 = 폴더** | 팀마다 로컬 폴더 1개. 대화 이력·팀 규칙·산출물이 팀별로 분리됨 |
| **팀장 = 봇** | 팀 폴더의 `.claude/agents/leader.md` 하나. 실제 작업은 Claude Code가 수행 |
| **팀원** | 화면에 자리와 상태만 표시 (벤, 뮤즈) |
| **프리랜서** | 필요할 때 등록하는 추가 봇. 공유석 1자리 |
| **wiki** | 공통 지식 창고. 팀장은 `raw/`에 후보만 넣고, `/wiki-ingest`가 정리 |
| **handoff** | 팀 간 산출물 전달 우편함 |
| **board** | 업무 보드 (`tasks.json`) |
| **결재** | Claude Code의 도구 권한 요청을 대표가 화면에서 승인/반려 |

## 3. 시스템 구조

```
┌──────────── 브라우저 (localhost:3000) ────────────┐
│  React 대시보드: 3D 사무실 · 상태카드 · 보드 · 패널 │
└───────────────▲──────────────────┬────────────────┘
        WebSocket (상태·스트림)     │ REST (지시·결재·설정)
┌───────────────┴──────────────────▼────────────────┐
│  Node 서버 (TypeScript)                            │
│  - LeaderRunner: 팀장별 Agent SDK 세션 관리        │
│  - EventMapper: SDK 메시지 → 화면 상태              │
│  - ApprovalQueue: 권한 요청 대기열                  │
│  - FileWatcher: board/, wiki/raw/, work/ 감시       │
└───────────────┬────────────────────────────────────┘
                │ cwd = teams/<팀>
┌───────────────▼────────────────────────────────────┐
│  Claude Code (Agent SDK) × 팀장 3                  │
│  + IdeaPrism 레포 파일 (wiki / handoff / board)     │
└────────────────────────────────────────────────────┘
```

### 3.1 기술 스택

| 층 | 선택 | 비고 |
|---|---|---|
| 프런트 | React + Vite + TypeScript | CSS 3D transform으로 사무실 표현 |
| 서버 | Node 20+ + TypeScript, `ws` | 로컬 전용 |
| 실행 엔진 | **Claude Agent SDK (TypeScript)** | 도구 승인 콜백을 결재 UI에 연결 |
| 대체 경로 | `claude -p --output-format stream-json --resume <id>` | SDK 연동 전 1단계 검증용 |
| 저장 | 로컬 JSON 파일 | DB 불필요 |

> 구현 시 SDK의 정확한 옵션명(작업 폴더, 추가 디렉터리, 세션 재개, 도구 승인 콜백)은 공식 문서로 먼저 확인한다. 참고: https://code.claude.com/docs/en/headless

## 6. 팀장 정의 · 팀 규칙 템플릿

### 6.1 `teams/<팀>/.claude/agents/leader.md`

```markdown
---
name: leader
description: IDEAPRISM [팀명] 팀장 [이름]. [팀명] 업무 요청을 처리한다.
tools: [5.2 허용 도구]
model: sonnet
---

# 정체성
[team_avengers/<이름>.md의 역할·말투·추임새를 그대로 옮김]
- 대표(창균님)에게 보고한다.

# 담당 업무
[5.2 담당]

# 일하는 방식
1. 작업 시작 시 ../../handoff/<내 팀>/ 수신함을 먼저 확인한다.
2. 산출물은 work/에 저장한다.
3. 다른 팀에 넘길 것은 ../../handoff/<받는 팀>/에 저장한다.
4. 끝나면 3줄 이내로 보고한다.

# 지식화 규칙
- 다음에도 재사용될 결정·기준·출처 있는 사실만 ../../wiki/raw/에 저장한다.
- 파일명: YYYYMMDD_<팀>_<주제>.md
- 대화 요약, 진행 상황, 추측은 저장하지 않는다.
- wiki/knowledge/는 읽기만 한다.

# 금지
- 페르소나 말투와 이모지는 대화 응답에만 쓴다. 파일에는 공식 문체로 쓴다.
- 다른 팀 폴더를 직접 수정하지 않는다 (handoff로만 전달).
- 확인되지 않은 수치·요건을 사실처럼 쓰지 않는다. 출처를 남긴다.
- board/tasks.json은 직접 수정하지 않는다 (서버가 관리).
```

## 7. 실행 엔진

### 7.1 팀장 실행

| 항목 | 값 |
|---|---|
| 작업 폴더 | `teams/<팀>` (config의 root 기준) |
| 에이전트 | `leader` |
| 추가 접근 | 5.2 표 |
| 세션 | 팀장별 세션 ID를 `office/.local/sessions.<PC>.json`에 저장, 다음 지시 때 재개 |
| 동시 실행 | 팀장 3명 병렬 허용. 같은 팀장은 한 번에 1개 작업 (나머지는 대기열) |
| 중단 | 패널의 "중단" 버튼 → 해당 실행 취소 |

### 7.2 SDK 메시지 → 화면 상태 매핑

| 수신 내용 | 상태 (`status`) | 화면 |
|---|---|---|
| 실행 없음 | `idle` 휴식 | 탕비실로 이동 |
| 실행 시작·텍스트 생성 중 | `thinking` 생각 중 | 자리, 보라 점 |
| Read / Glob / Grep 사용 (wiki 경로 포함) | `research` 자료 조사 | **도서관 스탠딩 테이블로 이동** (4.2초 후 복귀) |
| WebSearch / WebFetch | `research` 자료 조사 | 자리, 파란 점 |
| Write / Edit | `typing` 작성 중 | 자리, 주황 점 |
| Bash | `running` 실행 중 | 자리, 초록 점 |
| 권한 요청 (도구 승인 콜백) | `approval` 결재 대기 | **대표실 결재 테이블로 이동해 착석** |
| 결과 수신 | `done` 완료 → 10초 후 `idle` | 말풍선 "완료" |
| 오류 | `error` 문제 발생 | 자리, 빨간 점, 표정 이미지 `error` |
| 회의 모드 | `meeting` 회의 중 | 8인 회의 테이블 착석 |

> 도서관 이동은 **연출**이다. 팀장은 wiki에 상시 연결되어 있으며, wiki 경로를 읽을 때만 걸어가는 모습을 보인다. 이동 중에도 실행은 멈추지 않는다.

### 7.3 위치 결정 우선순위

`meeting` > `approval` > `research(wiki)` > `idle` > 자기 자리

### 8.3 사무실 씬

#### 시점과 표현
| 항목 | 값 |
|---|---|
| 시점 | 평면도의 **아래쪽(대표실 쪽)에서 뒤쪽 위를 내려다봄**. 바닥은 앞이 넓고 뒤가 좁은 사다리꼴 |

| 가구 | 상자형 3D (윗면·앞면·좌우면) — 책상, 모니터, 의자, 카운터, 소파, 테이블, 유리벽 |

| 이동 | `left/top` 1.6초 ease 전환 |
| 크기 맞춤 | 컨테이너 쿼리(`cqw/cqh`)로 비율 유지하며 영역에 꽉 차게 |

## 10. 주요 흐름

### 10.1 업무 지시
1. 팀장 클릭 → 입력 → 전송
2. 서버: task 생성(`doing`) → 해당 팀장 세션 재개해 실행
3. 스트림 수신 → 7.2 매핑으로 상태·위치 갱신 → WebSocket 전송
4. 결과 수신 → task `done`, 산출물 목록 갱신, 말풍선 "완료"

### 10.2 결재
1. 팀장이 권한이 필요한 도구 호출 → SDK 승인 콜백 → 서버가 Approval 생성
2. 팀장 상태 `approval` → 결재 테이블 빈자리로 이동, 결재함 배지 +1
3. 대표가 대화 탭 결재 카드에서 승인/반려
4. 콜백에 결과 반환 → 팀장은 자리로 복귀하며 작업 재개

**권한 기본값**

| 도구 | 기본 |
|---|---|
| Read, Glob, Grep, WebSearch, WebFetch | 자동 허용 |
| Write, Edit — 자기 팀 `work/`, `wiki/raw/` | 자동 허용 |
| Write, Edit — `handoff/`, `meetings/`, 팀 폴더 밖 | **결재** |
| Bash (개발팀) | **결재** (허용 목록 명령은 자동: `npm test`, `npm run lint`, `git status`, `git diff`) |
| `git push`, 삭제 명령 | **항상 결재** |

### 10.3 handoff
- 보내는 팀장이 `handoff/<받는 팀>/`에 파일 작성(결재) → 서버가 감지 → 씬에서 **서류가 날아가는 연출** → 받는 팀 카드에 "수신 1" 표시.
- 받는 팀장은 다음 실행 때 수신함을 먼저 확인 (팀 CLAUDE.md 규칙).

### 10.4 wiki 지식화
1. 팀장이 `wiki/raw/`에 후보 저장 (자동 허용)
2. 도서관 창의 raw 건수 증가
3. 대표가 `/wiki-ingest` 실행 → 사서 skill이 knowledge에 병합, index 갱신, raw를 `_done/`으로 이동
4. 결과 diff를 산출물 탭에서 확인 → 커밋

### 10.5 산출물 검토·커밋
- 산출물 탭은 마지막 커밋 이후 해당 팀 폴더 변경분을 `git diff`로 표시.
- "검토 완료 · 커밋" → 서버가 해당 파일만 커밋. 메시지: `[회사] <팀> <task 제목>` (기존 레포 규칙 따름).
- push는 하지 않는다 (사용자가 직접).

| A8 | handoff 파일 생성 시 받는 팀 카드에 수신 표시가 뜬다 |
| A9 | 회사·집 PC에서 `--pc` 옵션만 바꿔 같은 앱이 실행된다 |
| A10 | 서버는 외부 IP에서 접속되지 않는다 |
